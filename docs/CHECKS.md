# The verify checks

What each row of `pnpm verify` proves and what it stays blind to. `pnpm verify` prints only a short
footer on green; `pnpm verify --explain` prints every row's blind spot. The table below is generated
from `scripts/verify/registry.mjs` — `memo:drift` goes red if it differs; regenerate with
`pnpm verify:write`.

## What the fast tier does NOT prove, as a whole

These are the tier's gaps *as a whole*:

- **It does not build.** `template:check` runs `tsc` over a rendered mock, but no `vite build`, no bundle. Everything that breaks
  only in a bundle — the Tailwind `@source` line, asset paths, CSS variables absent from `dist` — is
  untouched until `pnpm verify:full`.
- **It does not run a browser.** No Playwright, no viewport, no deep link, no click. Nobody has
  looked at a pixel.
- **It does not measure coverage or mutation.** A test that cannot fail counts the same as one that
  can. `packages/dec/golden.json` was once generated by importing the module it tests: 675 cases
  asserted `dec === dec` and stayed green while `dec` rounded the wrong way.
- **It says nothing about a mock you have already scaffolded.** `mocks/<slug>` is its own TypeScript
  project, compiled only by its own build. The TEMPLATE is no longer in that category: `template:check`
  renders it and typechecks the result in this tier, which is what compiles the template's drift controls.
- **Prose is not gated.** `docs:truth` proves the paths in CLAUDE.md resolve. It cannot prove a
  sentence around one of them is still true.

| `api:bound` | fast | For templates/mock and every mocks/<slug>, each HTTP call made from ANY non-test, non-controls file under src/ names an operation the mock's own contract declares, and each declared operation is either reached from one of those files or carries a non-empty `unreached` reason on its registry entry. The marker is a RATCHET: absent while unreached is red, present while reached is red as stale, and empty is red because "" is not a reason. A mock DIRECTORY with no src/api/contract.ts is red rather than silently skipped, and `checked` counts registries actually parsed. It reads the TypeScript AST and anchors on the IMPORTED BINDING, resolving the specifier against the importing file, so a renamed import still counts and a `call` from @agency/contracts/api/contract does not. It reads TWO surfaces onto that registry — call(http, key, …) and the makeQueries factory's queries.query(key, …) / .mutation(key) / .keyOf(key), whose key is argument 0 — because a row blind to the factory reports every operation reached through it as unreached, which is a false red and the fastest route to a row an operator switches off. | It matches an operation NAME, never a response type: a correct key with an invented response type is green here, and that is permanently the drift controls' and the wire golden's job. The code clause is reachability by LITERAL, not by proof for EVERY code: routes.ts passes rule-returned codes as VALUES (blank.code), so argument 1 is an identifier this cannot name — for an operation with any such call the old file-wide literal search is used as a fallback, and a comment satisfies it there exactly as it used to satisfy it everywhere. | `checks:bite` | fast | For each fixture in the table — 21 today, over 19 distinct planted defects: a tree derived from templates/mock is GREEN with no defect in it, the same tree with exactly ONE defect planted exits 1 — not merely non-zero, so a SKIPPED or UNRUNNABLE check cannot pass as a failed one — and the failing output names the planted symbol. | `wire:frozen` | full (after: build) | On a mock scaffolded and installed from scratch, every declared operation is driven once through the REAL adapter AND every declared (operation, code) pair is driven as a refusal, with the exhaustiveness loop running at RUNTIME over Object.keys(api[key].codes) so a cast in the drive table cannot evade it. Each response reduces to a structural fingerprint of key names and value DOMAINS (balance:dec2, created_at:instant, id:seq-id, empty-body for a 204), each refusal to its STATUS plus the envelope's fingerprint, each MALFORMED body to the 400 and the `message: string[]` envelope a ValidationPipe rejection becomes, and all three are compared to the committed fixture — then REGENERATED and required to be byte-identical, so a fixture that passes only because the test stopped driving a route is red. This is the one mechanism here that catches a re-cased wire field: created_at -> createdAt typechecks perfectly when both sides are renamed together. The tokens are a fixed table, so a domain it does not know reduces to bare `string`. It drives each operation and each refusal exactly ONCE, with one set of arguments and ONE actor against the seeded store — so a second page is unfingerprinted, and a handler that branches on the actor is fingerprinted only for the branch that actor takes, which is one of the two exactness residuals this golden is supposed to be the ground truth for. A TRANSPORT failure declares no code, so it forms no (operation, code) pair and is driven by nothing here. It runs pnpm install, which rewrites pnpm-lock.yaml and then restores it byte for byte; a concurrent install in the same tree is not detected. The LIVE replay (AGENCY_LIVE_API) is not exercised by this row at all: unset, it reports SKIPPED through vitest's own describe.skipIf, so every run this repository can perform says nothing about whether a real backend agrees with the committed shapes. Only its one-entry equivalence map (seq-id <-> uuid) is tested unconditionally. |
